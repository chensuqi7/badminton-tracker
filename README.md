# 羽球日记 · MY BADMINTON V3.1 · 羽球生活

[打开羽球日记](https://chensuqi7.github.io/badminton-tracker/)

首页可一键记培训或打球。运动页可查看月历、年度热力图、课时流水和对账。开销页汇总六类消费、退款及年度趋势。我的可管理装备、穿线、训练目标、账号及导出。

本工作区的 V3.1 需与羽球生活数据库迁移配套发布。生产发布前应完成私有备份、审批与双账号验收。

## 本地试用

在项目根目录执行 `python3 -m http.server 8000 --bind 127.0.0.1`，然后访问 `http://localhost:8000/`。静态资源使用相对地址。首次联网后，Service Worker 缓存应用文件。云端登录和同步使用固定版本的 Supabase JavaScript SDK。

## 课时与消费

原有账本期初保留 22 节，新用户期初为 0。之前抵消的超课无需再次登记。校准期初与增减调整均保留流水。赠送训练只计训练次数，赠送课时增加余额。购课余额增量为购买加赠送减本次欠课抵扣。费用由购课流水生成，购课编辑、改类型或删除会同步重算账单。补录以往金额请在「开销」新增支出并选择「历史培训补录」，课时余额保持原样。培训购课支出占比按关联购课来源统计。

一级分类固定为打球费用、球鞋服饰、球拍装备、羽球耗材、穿线维护和其他。旧培训费用与场地费用归入打球费用，旧其他费用归入其他。迁移保留来源、关联 ID 和修改历史，并备份原 V3 账本。

金额以整数分保存。课程成本按日期先购先用，实际支付金额平摊至购买与随购赠送课时，退课移除最近批次余量。期初、独立赠送及缺少实付数据的消耗标为未知。余额与预计剩余周数按每周培训目标估算。耗尽日期用于训练规划。

## 保存与恢复

本地模式将账本保存在当前浏览器或已安装网页应用的本地存储中。读取旧课时流水时先备份原始值，再保存已校验的 V3 账本。V3 JSON 包含课时、支出、运动、球包、穿线、对账、设置与修改历史，关联费用由购课记录重建。也可恢复旧 JSON 备份。本地恢复前保留当前 V3 原文，云端恢复走合并预览和确认。两类 CSV 分开导出。

更换设备、浏览器或独立应用环境时，先导出 JSON，再在新环境导入。遇到迁移失败，可从设置导出原始数据。保留站点数据可保留账本。

## 安装和更新

用 iPhone Chrome 打开正式地址，点「分享 → 添加到主屏幕 → 添加」。如有「作为网页 App 打开」开关，开启后再添加。首次联网从图标打开，待缓存安装后即可测试离线启动。

GitHub Pages 使用个人仓库 `main` 根目录并强制 HTTPS。更新静态资源时同步更新 `sw.js` 的缓存版本与文件清单。提交并发布后，核对 Pages 线上资源与提交一致。旧界面可联网关闭并重新打开以加载新缓存。

## 云端同步

个人 Supabase 项目完成配置与权限验收后，在设置中使用已获授权的邮箱账号登录。首页显示同步状态，设置显示最后同步时间及待同步记录数。历史账本先在原设备导出 JSON，再逐台查看合并预览并确认导入。同步失败时保留 IndexedDB 草稿，恢复联网后会重试，也可点击「立即同步」。出现冲突时，先导出本机 JSON，再核对保留哪笔记录。数据库结构、权限测试及 SQL 备份见 [数据库设计](supabase/DESIGN.md)。


### 邀请试点

试点继续关闭公开注册。管理员在 Supabase Authentication → Users 手动创建并确认球友邮箱，然后登记该 Auth UUID。新账本从 0 节开始，原账号沿用 22 节和已保存的校准记录。云端 JSON 导出标记所属账号，旧备份需要核对所有者后确认导入。账号切换立即隐藏上一个账本。离线重新打开云账本前，请在私人设备的设置中启用「允许此设备离线打开」。重新打开时还需要能加载 SDK 并核对本机会话。


### 业务联动

- 培训由课时流水推导运动记录，删除或改期后自动更新。日常打球独立记事，可选填时长、地点及关联消费。
- 球包支持购买记账、关联已有账单或仅建档。退役保留历史。穿线历史按业务日期推导当前球线。
- 对账在服务器核对余额。余额一致时只保存对账；有差异时需填写原因并确认一条独立调整。已确认对账通过重新对账纠错。
- 首次登录加载完整账本，已同步设备按版本分页读取变动。Realtime 提示刷新，前台恢复和联网也会主动检查。
